## 입력

## 빗살이 처음 생기는 단계

합성 200×180 그림에서 흰 바탕(250,249,247)과 벽 참고색(246,244,240)은 가깝고, 오른쪽의 검은 획은 행마다 다른 깊이다.

- `paintBorderWall` 직후, 오른쪽에서 `#f3f3f3`로 칠해진 길이가 이웃 행과 2픽셀 이상 달라지는 자리가 4곳을 넘었다.
- 같은 종류의 흰 바탕·검은 획을 둔 그림에서, 모서리를 캔버스 밖에 두고 새 기하로 편 출력에는 `#f3f3f3` 픽셀이 0개였다.

그래서 빗살은 기하 샘플링 이전이 아니라, 직선으로 편 뒤 색으로 안쪽을 칠하는 단계에서 생긴다. 사각형 경로는 그 함수를 호출하지 않는다. 휘어진 벽 띠는 그 함수를 꺼도 남으므로, 경계 추적과 역매핑으로 따로 뺀다.

## 합성 측정

긴 변 220px, 알려진 `k1 = 0.85` 의 잔여 방사 왜곡. 왜곡 생성은 테스트 안의 독립 구현이다.

| 항목 | 측정 |
|---|---|
| 복원된 k1 | 0.81 (차이 0.04) |
| 방법 / 상태 | `radial` / `applied` |
| 모서리 (0,0) → 원본 모서리 | 0.05px 미만 |
| held-out 잔차 | 약 0.63px (원본 좌표) |
| 2048 긴 변으로 환산 | 약 5.9px |

환산 잔차는 지시서의 0.5px 제안 기준에 못 미친다. 추적 점이 반픽셀 단위라 약한 휨에서는 계수 오차가 남는다. 기준을 테스트가 통과하도록 바꾸지는 않았다.

모서리를 8px 밖에 둔 직선 그림:

- 오른쪽 흰 바탕의 검은 획을 외곽으로 따르지 않았다.
- 출력 왼쪽은 그림 색, 오른쪽은 흰 바탕이었다.
- 벽과 같은 RGB를 그림 안에 둔 픽셀은 출력에 남았다.

반듯한 정면 사각형은 `identity` / `already_straight` 이고, 샘플 픽셀이 입력과 같았다. 곡률 끄기는 `disabled` 이고 방사 계수를 넣지 않았다.

## 저장

`geometry` 는 `enhancement_meta` JSON 안의 flat 레시피 필드다. 정규화 왕복 후 method, status, aspect source 가 남았다. `k1` 이 NaN 인 계획은 메타 전체를 거절한다. 세션 프리셋은 `edgeCurvature` 만 읽고, 계수와 모서리는 읽지 않는다.
