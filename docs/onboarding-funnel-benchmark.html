매끄러운 온보딩의 7가지 원칙

1. 가치까지의 시간 최소화TTV

가입은 콘텐츠를 보기 위한 통행료가 아니라 “더 얻기 위한 문”이어야 함. 열람은 계속 열어두고, 가입 순간의 단계 수를 줄인다.

2. 맥락형 게이팅Context

의도가 최고조인 “클릭 직후”에 게이트를 걸되, 무엇이 열리는지를 화면에 보여준다(클릭한 작품 썸네일·제목).

3. 결정 지점의 소셜 프루프Proof

이미 만든 페르소나 실시간 카운터를 가입 화면에 재활용 — “아티스트 N · 컬렉터 M명이 함께” 형태로 FOMO 자극.

4. 원탭 인증1-tap

Google/Apple/Kakao 소셜 로그인은 이메일 확인 벽을 통째로 제거한다. 단일 변경으로 가장 큰 마찰 감소.

5. 점진적 프로파일링Progressive

identity 전체를 한 번에 받지 말고, 콘텐츠 잠금 해제에 꼭 필요한 최소치만 받고 나머지는 이후에 인라인으로 수집.

6. 투자/커밋먼트Commit

방문자가 먼저 무언가(좋아요·저장·팔로우 시도)를 하게 한 뒤 가입을 청하면, 이미 들인 노력이 완료 동기를 만든다.

7. 연속성 (이미 구현)
클릭한 상세를 next로 넘겨 가입 완료 후 그 화면으로 복귀 — 이번 패치로 확보됨. 나머지 6개가 다음 개선 여지.

제안: 가장 매끄러운 흐름(To-be)

A. 브라우즈

콜드 방문자는 피드를 자유롭게 열람. 작가명 등만 블러. 상단에 슬림한 실시간 페르소나 카운터로 규모감·FOMO.

B. 맥락형 게이트

상세 클릭 시 “이 작품을 계속 보려면” + 작품 썸네일/제목 + Google·Apple 원탭. 이메일은 보조 옵션.

C. 즉시 입장 · 나중 완성

원탭이면 확인 벽 없이 바로 입장 → 원래 상세로 복귀. 이름 1필드만 받고 역할·핸들은 이후 인라인 넛지로 점진 수집.

가장 큰 레버 두 개: 소셜 원탭 로그인 맥락형 가입 화면 + 소셜 프루프 이 둘만으로 3·5단계 이탈을 대부분 해소.

다음 액션 후보

원하시면 (1) Supabase Google/Apple/Kakao OAuth 연동 + 로그인·온보딩 화면 버튼, (2) next가 작품일 때 히어로+페르소나 카운터를 얹은 맥락형 가입 화면부터 착수할 수 있습니다.
